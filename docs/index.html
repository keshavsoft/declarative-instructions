The Story of declarative-instructions

A versioned catalog of JSON instructions: each entry describes the source to read, the transformation and template to use, and the destination to update.

Open the V4 instruction catalog →

Decoupling the "How" from Compiler Code

In traditional web development, a compiler contains hundreds of lines of imperative DOM traversal code: finding containers, creating child elements, iterating arrays, and appending nodes.

This package stores reusable instruction definitions as JSON. A consuming runner interprets those definitions against its current state; this package itself does not transform data or mount DOM.

The 4-Part Instruction Contract

The V4 catalog describes each operation with fields whose shape depends on the kind of work:

  • sourcePath: Where a runner reads input values, such as $.data.columns.
  • func: The transformation to apply, such as fromCollection or rowOnColumn; static actions can use null.
  • templateKey: The template name or row and column template names from the spec catalog.
  • destinationPath: The JSONPath location to update, with an optional write action for static steps.

Instruction Rule Example 

{
          "buildBody": {
    "sourcePath": {
      "rows": "$.data.data",
      "columns": "$.data.columns"
    },
    "templateKey": {
      "rowKey": "buildBodyTr",
      "columnKey": "buildBodyCell"
    },
    "func": "rowOnColumn",
    "destinationPath": {
      "jsonPath": "$..*[?@.attributes['data-role'] == 'table-body'].children"
    }
  }
}
